# 文档总览

仓库文档按作用域和稳定程度分层，避免把某个插件的设计细节写进仓库总览。

## 文档层次

### 仓库级

根 [`README.md`](../README.md) 只说明仓库定位、当前插件、通用开发命令和跨插件约定。

### 插件级

每个插件在 `packages/<name>/` 下维护自己的 README、上下文、决策记录和调研材料。当前插件：

- [`dsh-space`](../packages/space/README.md)

### 设计级

- `CONTEXT.md`：稳定领域术语、事实源和不变量。它不记录具体实现步骤
- `docs/design.md`：当前实现设计、模块职责、状态流转、测试策略和演进路线
- `docs/adr/`：难以逆转、容易被误解或存在明确权衡的架构决策
- `packages/<name>/docs/research/`：支持具体插件设计判断的一手资料和对标分析

## 阅读顺序

新贡献者建议按以下顺序阅读：

1. 插件 README，了解能力和用户可见边界
2. `CONTEXT.md`，掌握术语和事实源
3. `docs/design.md`，理解模块和运行链路
4. 相关 ADR，确认关键取舍
5. 对应插件的 `docs/research/`，需要追溯依据时再阅读

## 文档维护规则

- 用户如何使用插件，写在插件 README
- “这个词在本项目中是什么意思”，写在 `CONTEXT.md`
- “现在准备怎样实现”，写在 `docs/design.md`
- “为什么选择这个方案而不是其他方案”，写在 ADR
- 外部资料只放在 research，并在正文中注明资料口径和时点
