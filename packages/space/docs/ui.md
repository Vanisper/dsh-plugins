# 交互设计与验收

## 立场

本插件为 DSH 的官方 Workspace 提供多目录组织和日期对话目录。UI 应围绕普通 Workspace、Space、Member 和 Chat 的实际关系设计，不另建会话归属或排序机制。多根读写权限不在本期规划内。

用户提供的 Codex 截图与描述是交互观察，不是宿主机制规格。可参考入口区分、渐进展示、成员编辑和状态反馈，但不据此推断其目录分配、权限或会话创建原理，也不要求组名与布局逐项一致。

## 核心流程

| 流程 | 本插件的语义 | 交互验收方向 |
| --- | --- | --- |
| 添加普通 Workspace | 显式登记已有目录，不添加 Space 描述 | 目录选择、重复目录反馈、取消不产生变更 |
| 创建 Space | 新建固定壳目录及核心身份，可没有成员 | 明确名称与成员的区别，支持多个源目录及提交前编辑 |
| 增强普通 Workspace | 为已有核心身份添加组织描述 | 保留路径、名称、历史会话和顺序 |
| 新建会话 | 在指定核心 Workspace 中开始对话 | 入口明确当前归属，不因主成员变化切换 cwd |
| 创建 Chat | 使用日期目录承载独立对话 Workspace | 与创建 Space 的入口、命名和反馈可区分 |
| 编辑成员 | 修改成员集合、显示名、说明和主成员 | 稳定列表、可辨认的完整路径、设主反馈和可靠取消 |
| 移除描述 | 退化为普通 Workspace | 不删除核心身份、目录或会话 |
| 移除核心 Workspace | 由官方服务移除登记 | 清楚说明保留目录与会话日志，失败时保留可恢复状态 |

“进入新对话预备视图”与“持久化新会话”应区分。是否延迟创建 Chat 目录，需要先核对宿主公开的会话启动契约，再决定交互；不能从参考截图推定能力，也不能引入一套独立的会话生命周期。

## 合并后的完善范围

### 创建与成员编辑

- Space 创建支持零个或多个源目录，按真实路径去重
- 编辑时明确草稿、提交和取消边界；部分失败可继续操作，不把失败伪装成成功
- 主成员具有清晰标记，可在展示层置顶并提供适度动画，但不改变核心会话归属
- 相同目录简称显示足够路径上下文，始终支持完整路径定位
- 普通 Workspace 增强、移除描述和移除核心登记分别表达，避免误删理解

### 侧栏与会话

- 普通 Workspace、Space、Chat 的入口语义明确，分组仅为核心数据的投影
- hover 或聚焦呈现常用操作，触屏和键盘同样可达；必要时提供上下文菜单
- 会话跳转、搜索、改名、分叉、归档与排序保持官方行为
- 折叠、当前会话定位和排序具有稳定反馈，控件不会造成布局跳动
- 未归组、空态、加载、失败、失效描述和断线恢复均有可操作的状态

### 一致性与可访问性

- 图标、间距、颜色与宿主保持一致，名称和路径过长时不挤占操作区
- 弹窗有焦点管理、Escape 关闭、焦点回归与可访问名称
- 异步提交防重复，进行中控件状态一致，错误显示在发生操作的位置
- 在宽侧栏、收起侧栏、窄屏与触屏视口检查遮挡、滚动和菜单定位

## 阶段门禁

每阶段先确认领域规则和失败语义，再实现交互；UI 测试反哺逻辑时补充对应回归测试。至少通过构建、类型检查、lint、自动化测试和受影响流程的真实浏览器验收，之后检查代码与文档是否存在临时诊断、重复状态或失效描述。

当前 PR 收尾负责机制和已有交互闭环，不把本页列出的后续 UI 完善项宣称为已完成。下一阶段从实际任务场景选择最小完整流程推进，不以复制参考产品作为完成标准。
