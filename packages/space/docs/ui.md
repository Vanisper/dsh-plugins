# 交互设计与验收

## 立场

本插件为 DSH 的官方 Workspace 提供多目录组织和日期对话目录。UI 应围绕普通 Workspace、Space、Member 和 Chat 的实际关系设计，不另建会话归属或排序机制。多根读写权限不在本期规划内。

用户提供的 Codex 截图与描述是交互观察，不是宿主机制规格。可参考入口区分、渐进展示、成员编辑和状态反馈，但不据此推断其目录分配、权限或会话创建原理，也不要求组名与布局逐项一致。

## 核心流程

| 流程 | 本插件的语义 | 交互验收方向 |
| --- | --- | --- |
| 添加普通 Workspace | 显式登记已有目录，不添加 Space 描述 | 目录选择、重复目录反馈、取消不产生变更 |
| 创建 Space | 新建固定壳目录及核心身份，可没有成员 | 明确名称与成员的区别，支持多个源目录及提交前编辑 |
| 增强普通 Workspace | 为已有核心身份添加组织描述 | 保留路径、名称、历史会话和顺序 |
| 新建会话 | 在原生输入区编辑无实体草稿，首次提交创建真实 Session | 创建前无节点，创建后可见；不因主成员变化切换 cwd |
| 创建 Chat | 独立对话首次提交时使用日期目录承载 Workspace | 开始编辑、添加图片和选择配置均不分配目录 |
| 编辑成员 | 修改成员集合、显示名、说明和主成员 | 稳定列表、可辨认的完整路径、设主反馈和可靠取消 |
| 移除描述 | 退化为普通 Workspace | 不删除核心身份、目录或会话 |
| 移除核心 Workspace | 由官方服务移除登记 | 清楚说明保留目录与会话日志，失败时保留可恢复状态 |

“开始草稿”与“持久化新会话”应区分；插件遵循下文的宿主会话创建契约，不引入独立的会话持久化。

## 上线交互契约

### 创建与成员编辑

- Space 创建支持零个或多个源目录，按真实路径去重
- 创建表单与成员编辑均使用本地草稿，添加、移除、改名、说明和设主只在保存时提交；取消不写入
- 整份成员草稿先校验再保存；使用描述内容版本拒绝过期覆盖，冲突时保留草稿并提供显式重新载入
- 编辑时明确草稿、提交和取消边界；部分失败可继续操作，不把失败伪装成成功
- 创建成功但核心列表尚未同步时，已提交表单只读；重试只进入同一核心身份，关闭不撤销已完成的创建
- 主成员具有清晰标记，可在展示层置顶并提供适度动画，但不改变核心会话归属
- 相同目录简称显示足够路径上下文，始终支持完整路径定位
- 普通 Workspace 增强、移除描述和移除核心登记分别表达，避免误删理解

### 侧栏与会话

- 空间模式内以“工作区 / 分组”切换同一批会话的展示；该切换与底部“官方 / 空间”模式切换独立
- 侧栏由“置顶 / 独立对话 / 工作区”三个可折叠、可拖动排序的大分区构成，菜单提供键盘和触屏的排序入口
- 普通 Workspace 与 Space 在工作区分区内嵌套会话；Chat 会话在独立对话分区内按活动时间平铺。未归组历史会话单独标明，不推断为 Chat
- 工作区和单个会话均可置顶；置顶项移入置顶分区，不重复显示。取消置顶恢复核心归属与顺序；同时置顶工作区和其会话时，会话独立展示，不在工作区下重复
- 大分区顺序、折叠与有序置顶引用是当前浏览器来源的展示偏好，跨页同步；存储受限时退回内存。不向核心注册表写入置顶或分区关系
- 工作区与普通会话的排序通过官方接口提交，置顶区内的排序只调整展示引用。独立对话按活动时间排列，不提供与此规则冲突的手动排序
- 大分区和工作区内长列表默认显示五项，当前会话及其工作区始终保留在可见集合中；支持展开与收起。主动折叠当前分区不会被轮询强制展开
- 独立对话分区以新对话图标开始草稿，工作区分区以加号选择创建空间或登记目录；折叠不影响创建入口。“管理对话目录”保留空白及已归档对话目录的管理入口
- 会话行提供置顶和归档快捷动作；归档失败保留原位置和置顶，成功后移除置顶引用但保留分组标记
- 工作区标题悬停展示完整目录、会话数量和成员摘要；项目内会话悬停展示完整标题、状态、更新时间及所属工作区。信息只使用宿主实际提供的数据，不推断设备、Git 状态或权限
- 独立对话不自动弹出项目归属浮层；所有信息及改名入口均可通过菜单访问，不要求触屏模拟 hover
- 浮层延迟出现，指针可以移入操作；键盘打开时移动焦点，Escape 关闭后回到原条目。路径与长名称在浮层内完整换行
- 浮层标题支持原位改名，显式保存或取消，不在失焦时自动提交；失败保留草稿，保存时防重复，编辑期间阻止模式切换。Escape 先取消编辑，再关闭信息
- hover 或聚焦呈现常用操作，触屏和键盘同样可达；必要时提供上下文菜单
- 会话跳转、搜索、改名、分叉、归档与排序保持官方行为
- 折叠、当前会话定位和排序具有稳定反馈，控件不会造成布局跳动
- 未归组、空态、加载、失败、失效描述和断线恢复均有可操作的状态
- 附加描述不可用时禁止移除核心工作区；确认移除前复核当前描述，核心移除失败后重试不重复清理描述
- 失效描述逐条确认并复核失效状态，不自动批量清理
- 全文搜索依赖宿主索引；不可用时保留标题匹配并提供重试。已创建的空白会话同样进入列表、置顶、分组、搜索与可见会话数量

### 展示分组与排序

- 工作区视图保留上述三个分区；批量展开或收起只控制工作区条目，不折叠独立对话或独立置顶的会话
- 工作区支持核心手动顺序和最近活动排序；活动排序仅作用于展示，不能同时拖动或调用核心手动排序
- 分组视图平铺全部正常可见会话，包括普通 Workspace、Space、Chat 和未归属会话；工作区置顶不隐藏其会话，单独置顶的会话仍只展示一次
- 每个会话最多一个展示分组，标记不影响核心 Workspace、cwd、成员或权限。取消置顶后恢复分组位置；归档保留标记
- 分组支持创建、改名、颜色、折叠、排序与移除。移除分组只清理标记，会话回到未分组列表，不删除会话
- 分组标记、分组顺序及视图偏好沿用当前浏览器来源的存储范围，重新打开保留、跨页同步；不是宿主级同步或会话归属事实源
- 分组会话支持最近活动和标题排序，不另建会话手动顺序；支持拖入分组及菜单分配，触屏与键盘不依赖拖动
- 会话创建不继承展示分组作为工作目录；新增分组不创建 Workspace 或目录

### 归档视图与后续能力

- 会话归档采用原地两步确认；第二次明确确认才调用官方归档，Escape 或点击外部取消。提交中防重复，失败保留原位置、置顶与错误反馈
- 归档入口在两种视图中常驻；归档列表替换列表区域，关闭后恢复原视图、搜索和滚动位置
- 归档列表以官方归档集合为唯一依据，展示会话标题、更新时间与可确定的原工作区，支持标题和工作区匹配、最近活动或标题排序；当前只展示摘要，不通过打开会话隐式恢复运行
- 当前仅支持查看归档列表。取消归档与永久删除属于后续计划，入口禁用并标明“计划支持”；说明当前宿主能力未接入，不发送写请求、不伪装成功
- 后续取消归档需通过宿主串行写入恢复标记、保留原归属和顺序；永久删除需先补会话生命周期、持久化、引用和索引清理及失败恢复契约，不删除工作目录或产出文件

### 一致性与可访问性

- 图标、间距、颜色与宿主保持一致，名称和路径过长时不挤占操作区
- 弹窗有焦点管理、Escape 关闭、焦点回归与可访问名称
- 异步提交防重复，进行中控件状态一致，错误显示在发生操作的位置
- 在宽侧栏、收起侧栏、窄屏与触屏视口检查遮挡、滚动和菜单定位
- 弹窗内容独立滚动，底部操作始终可见；展开成员详情可直接读取完整路径

### 模式切换

- 在侧栏底部提供“空间模式 / 官方模式”切换，两个模式始终都有入口
- 官方模式撤销增强侧栏、原生草稿扩展和工作区选择器，并移除插件样式，恢复官方组件、新建方法及启动选择策略；底部切换器独立注册于 `sidebar.footer.action`
- 模式偏好按当前浏览器来源保存，跨页同步；存储不可用时仍可在当前页面切换
- 离开空间模式时正在编辑草稿，切回后直接恢复该草稿、目标与配置，不沿用官方自动选中的真实会话；离开时已经选中真实会话，则保留真实会话选择
- 插件切换不改写 Workspace、Session、Space/Chat 描述或沙箱权限；官方策略恢复后的行为由宿主负责。进行中的提交不得被主动切换打断
- 插件卸载清除注册、样式、轮询和监听器，保留官方数据

### 会话创建

- 空间模式的新会话入口都进入同一原生输入区的草稿态。顶部通用入口沿用当前编辑上下文：项目内真实会话使用其核心工作区，项目草稿保留目标，独立对话或独立草稿不选项目；未归属会话不回退到最近工作区。工作区专属入口预选该身份，明确的独立对话入口始终不选项目。创建 Space 仍是显式目录操作，完成后开始该空间的草稿
- 通用新建从真实会话读取归属时，以核心列表决定身份，只读附加描述区分项目与 Chat 存储工作区；读取失败保留原位置并提示重试，不猜测目录类型。期间发生导航、显式选择、模式切换或卸载时，取消旧请求；核心归属变化时拒绝应用旧结果。已有草稿的正文、配置及创建重试目标锁保持不变
- 编辑文字、粘贴图片、选择模型、推理等级、访问模式以及计划或目标意图均不创建实体。选择工作区只更新目标意图，不把主成员路径当作 cwd；候选按名称和路径搜索普通 Workspace、Space，排除 Chat 目录
- 输入区加号和前导 `/` 共用原生命令视图、搜索与键盘选择，保留原生分组标题与候选顺序，不添加图片入口。计划、目标命令的浅提示说明当前可执行动作，其他命令保留原描述。目录合并宿主当前默认预设的命令描述和前端注册，下一次打开反映新增和卸载；未知或依赖真实会话的命令逐项禁用，悬停及点击提示原因。读取失败可以原位重试
- `model`、`permission` 使用原生选项弹窗，只改当前草稿配置；Full access 沿用原生风险确认。配置操作保留正文和图片，只消费输入触发的命令文本
- `plan`、`goal` 点选即开启对应模式，再次确认同一命令取消；选择另一模式则切换，取消保留正文与附件。菜单提示分别在“开启计划模式／退出计划模式”和“开启目标模式／取消目标模式”之间变化，不插入命令文本或增加开关步骤
- 模式标记在权限旁以分隔线、灰色图标和“计划／目标”显示；悬停或键盘聚焦时图标变为取消，控件尺寸不变，触屏直接显示取消图标。普通模式不显示标记。输入提示分别为“有什么需要一起完成？”“描述需要规划的任务…”“描述目标和预期成果…”，创建期间不可改变模式
- 裸 `/plan`、`/goal` 执行同样的开启、切换或取消操作，不发送附件；目标模式也允许前导 `/` 候选选择。带正文的前导 `/goal` 可从非目标模式转换为目标意图和正文，`/plan <内容>` 保留原生命令解析，首次发送才创建实体。除显式裸模式命令外，目标正文不递归执行其中的命令；行内 `/` 与原生一致，排除接收正文的命令，不把换行解释成第二条独立命令
- 目标内容只在交给真实输入时编码为原生目标命令；空目标、`clear`、`pause`、`resume` 和 `edit` 管理参数在创建前拦截，正文和附件保留。已有目标的查询、暂停、恢复、编辑与清除在真实会话执行，取消草稿意图不修改真实目标。`/plan off` 只关闭草稿计划意图
- 附件沿用原生粘贴、拖入和资源交付，不提供独立文件选择入口。原生粘贴是用户触发的输入框事件，不是后台监听剪贴板
- 首次提交后锁定目标及配置，必要时创建 Chat，再通过官方 `sessions.create` 创建指定 Session ID。不复用任意空白 Session，也不以占位节点代替创建
- 创建成功立即出现真实节点，`blank` 只描述内容状态。无身份到首个身份使用同一输入 DOM；模型、权限和 Plan 选项应用后调用原生提交，不经过第二个准备或确认页面
- 创建响应丢失时复用固定 `creationId` 与请求 Session ID，核对核心归属后恢复。已有目标输入或已开始的会话不能被覆盖、追加或自动重发
- 真实输入接收内容后，配置或发送前校验失败保留输入与节点；宿主已经接受消息后的运行失败，按其消息记录与重试机制处理，不从草稿副本重复发送。创建前失败仍留在草稿态，提供错误并可重试
- 用户导航离开后，迟到创建结果不抢回当前会话、不自动发送。丢弃草稿需要原位二次确认，不能删除已经创建的实体
- 草稿只保留在页面内存中；刷新和关闭时请求浏览器确认，不承诺刷新、关闭或插件卸载后的恢复。切换官方模式保留本页草稿；从草稿离开时，切回空间模式即可继续编辑
- 已有 Session 的工作区选择继续由宿主处理；官方模式恢复原选择器、原始组件和样式

兼容扩展仅支持已校验的 DSH 0.1.1-rc.2 构建。原生输入状态机从固定发布包按符号依赖提取，根布局、实例新建方法和启动选择 effect 集中扩展，保留原注册身份与子 slot 授权，退出后恢复。插件装载前已创建的真实实体不删除、不隐藏；未知构建保留官方界面并提示原因，不能通过绕过校验声称兼容。

## 阶段门禁

每阶段先确认领域规则和失败语义，再实现交互；UI 测试反哺逻辑时补充对应回归测试。至少通过构建、类型检查、lint、自动化测试和受影响流程的真实浏览器验收，之后检查代码与文档是否存在临时诊断、重复状态或失效描述。

上线门禁覆盖：普通目录、空空间、多成员空间、独立对话、草稿取消、并发冲突、排序、搜索、归档、降级恢复和双向模式切换。测试报告记录实际完成范围，不以复制参考产品作为完成标准。

当前版本的执行结果见 [上线验收记录](acceptance.md)。
