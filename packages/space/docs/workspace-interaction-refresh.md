# 工作区交互整理

状态：2026-09-08 已确认实施，创建、编辑与状态切换、快速对话两阶段已完成，拖拽待实施。下列调查结论记录改版前状态；当前实现契约见 `ui.md` 与 `design.md`。

## 目标与边界

- 整理目录工作区与空间的创建、编辑，采用一致的表单结构
- 隐藏成员显示名称、说明的编辑字段，保留数据及既有值
- 将成员链接、空间化作为编辑草稿中的状态切换，保存时生效
- 收敛独立对话入口，补齐工作目录访问与基础目录结构
- 统一现有拖拽场景的落点规则和反馈，不新增跨工作区迁移能力

参考截图采用名称输入、紧凑目录列表、明确的添加入口和底部操作布局；不照搬其目录权限含义，不改变宿主的权限模型。

## 调查结论

### 链接和空间描述

成员所属关系来自 Space 的 `members`，不来自文件系统中的链接。`reference` 是默认形态，`link` 额外在核心工作目录的 `projects/<linkName>` 下建立符号链接。两者均不自动授予跨目录权限。

目前 [成员草稿校验](../src/business/member-draft.ts) 明确拒绝已有成员改变 `mode` 或 `linkName`；[成员编辑器](../src/client/member-editor.ts) 因此把既有接入方式展示成只读文本。放开切换不仅是替换控件，还必须补充已有路径的链接变更处理。

移除 Space 描述目前只修改插件设置，保留核心工作区、名称、路径、会话、文件及已有符号链接。丢失的是整份成员配置，包括路径集合、主成员、链接名称、显示名和说明；成员提示词投影随之消失。重新增强为空间不会自动找回这些配置。

因此，这两种操作可以采用轻量交互，但不能把符号链接清理失败、描述写入失败或降级损失隐藏成一次无条件成功的开关。

### 图 7 的来源

[侧栏的对话目录面板](../src/client/sidebar.ts) 使用 `items.filter(item => item.kind === 'chat')`，不扫描 `chats/` 目录推断类型。[投影规则](../src/business/lookup.ts) 按核心 Workspace ID 匹配插件描述，没有描述的核心工作区仍是 `plain`。

只读检查本机设置与核心登记的结果：

- 10 个有效 Chat 工作区，与图 7 的目录列表相符
- 同一托管 `chats/` 树下另有 7 个普通工作区，它们没有 Chat 描述，不属于图 7 的清单
- 2 个 Chat 工作区分别登记了 2 和 5 条会话，其中后者有 2 条已归档；数量本身不能区分普通新建和分叉，不能据此判定所有多会话目录都异常

目录面板目前确实提供“在此新建会话”。[通用新建入口](../src/client/new-session.ts) 在没有显式目标时会避开当前 Chat 工作区，但显式传入工作区 ID 会直接开始草稿；[草稿提交](../src/client/draft-session.ts) 也没有拒绝复用已占用 Chat 目录。这是需要收敛的入口，不是路径识别错误。

目前的会话悬停及浮层目录入口也明确排除了 `kind === 'chat'`，所以独立对话缺少工作目录访问，是现有规则造成的，不是没有真实工作区。

### 分叉与独占

宿主 0.1.1-rc.2 的 Session 分叉保留原 `cwd`，记录父会话并继承历史。强制分配新空目录会使历史中的文件与路径失去对应；复制文件则引入另一套快照与同步语义。

建议将约束定义为：**一次独立对话及其分叉共享一个专用的核心工作区；普通新建的独立对话另建工作区。**

这不需要再建立会话归属表。工作区及归属仍由官方注册表提供，Chat 仅表示该工作区用于快速独立对话。子代理不是第二个独立对话，不能简单用原始 `sessionIds.length === 1` 做约束。

插件应守住自身的新建入口，但不能声称在官方模式或插件停用后仍强制限制官方 Workspace 的全部使用方式。旧的多会话工作区保留原样，不自动拆分、移动文件或丢弃描述。

## 创建与编辑

### 共用结构，不混淆创建行为

| 场景 | 名称 | 核心工作目录 | 成员目录 |
| --- | --- | --- | --- |
| 添加目录工作区 | 选择目录后预填末级名称，可调整 | 用户选择的已有目录 | 默认不启用，显式作为空间时可添加 |
| 创建空间 | 用户输入 | 插件新建的固定壳目录 | 可为空，也可添加多个 |
| 编辑工作区 | 可修改 | 只读，提供打开或复制入口 | 由“作为空间”复选框控制 |

创建和编辑复用名称行、目录行、成员列表及底部操作结构，不把成员目录误当成核心目录。切换主成员不能改变核心 `cwd`。

成员列表采用统一边界的紧凑列表：目录图标、名称、次级路径、主要标记、链接复选框和移除按钮。空列表本身提供可点击的添加目录区域；非空列表底部保留添加入口。手动路径按需展开。

成员显示名与说明不再占用表单。已有值必须随草稿完整保留，不能因字段隐藏而提交空值；新成员默认使用目录名称。相同目录简称以路径消歧。

主成员仍用单选语义，只有一个成员时不显示多余的选择控件；多个成员时保持明确的当前主要标记。所有操作在本地草稿内完成，取消不写设置或文件系统。

### 成员链接切换

用户已确认允许已有成员直接切换。复选框表达“在工作区内创建链接”，不再展示 `reference / link` 下拉框。

| 切换 | 成员描述 | 文件系统 |
| --- | --- | --- |
| reference → link | 保留同一成员，改为 link | 创建或验证 `projects/<linkName>` |
| link → reference | 保留同一成员、显示名、说明及主成员状态 | 只移除与原描述及目标匹配的符号链接 |
| 移除成员 | 从集合移除，必要时调整主成员 | 按原有规则清理匹配链接，不删除源目录 |

默认链接名使用目录名。名称冲突时需展示实际目标及可调整的链接名，不能覆盖文件、静默删除别人的链接或以隐藏规则改名；既有自定义链接名也不能在隐藏字段时丢失。

保存前校验完整变更集，包括名称冲突、实际路径和描述版本。开启链接失败不提交新的成员模式；描述保存失败只清理本次新建的链接。关闭链接后的清理失败必须明确反馈并提供重试，不能沿用只记日志却对用户显示完全成功的方式。

### 空间化切换

在工作区编辑中提供双向的“作为空间”复选框，不再用“移除附加描述”弹窗完成正常降级。

取消勾选时仅修改草稿，保留本次编辑中的成员输入；重新勾选可以恢复。保存后才真正移除 Space 描述。有成员时就地提示将移除多少项成员配置，源目录、已有链接与会话保持不变，不再叠加一个大弹窗。

已有链接留在文件系统，不代表该工作区仍拥有 Space 成员关系。降级不顺便清空 `projects/`，再次增强不根据目录或链接自动重建成员。

有损降级的保存不应被输入框的隐式 Enter 触发，用户可点击保存，或明确把键盘焦点移到保存按钮后确认。保留 Escape、取消以及安全的初始焦点。

描述移除的版本校验需进入服务端串行操作，不能只依赖客户端提前读一次。名称与描述仍是分步保存；后一步失败保留已完成结果及重试信息，不承诺跨存储原子事务。

### 移除工作区

移除核心登记与关闭空间化仍是不同操作。移除入口保留在编辑底部的次要危险操作区，确认框缩为名称、必要路径和简短的保留范围说明，不重复展示大片字段。

必须说明：文件和会话日志保留，但核心工作区登记及其原分组关系会消失。取消确认返回编辑器，并恢复未保存的草稿，不把用户带回空白状态。

Chat 转为普通工作区是解除快速对话专用语义，不等同于 Space 取消成员管理，不把这两件事合并成含糊的“移除附加描述”。常用目录面板不再复用普通工作区的完整管理菜单。

## 快速工作区

### 新建、分叉与访问

- 普通新建独立对话：首次发送时分配新的 Chat 工作区
- 分叉独立对话：沿用原官方工作区及文件，保留官方分叉关系
- 同一次创建失败重试：复用原创建标识与工作区，不能额外分配目录或会话
- “对话目录”清单：保留空目录、已归档对话及历史数据的访问兜底，移除“在此新建”及无关的通用项目操作
- 会话悬停：展示标题、状态和真实工作目录，可直接打开目录；菜单提供同等入口，不要求键盘和触屏模拟 hover

专用工作区不应通过目录清单、显式新建参数、添加已有目录的重复登记结果等入口被重新当作通用新建目标。共享校验必须覆盖最终创建边界，同时保留已固定创建标识的合法重试。附加描述读取失败时，新建入口不能猜测其类型后继续写入。

### work 与 outputs

用户已提出预置两个目录。本方案将“快速工作区”限定为新建独立对话使用的 Chat 工作区，不自动修改已有普通目录或 Space。

```text
chats/<本地日期>/<名称>/
  work/
  outputs/
```

`work/` 用于过程文件和工作材料，`outputs/` 用于交付产物。系统提示词只追加一句用途说明，不生成额外说明文件，不移动文件，也不扩大读写权限。

目录准备纳入现有创建凭据与重试流程：只在首次实体创建阶段执行，不在打开草稿、悬停或读取注册表时创建。请求重试补齐缺少的目录，保留已有内容；遇到同名普通文件或符号链接时明确报错，不覆盖或跟随到工作区之外。

现有快速工作区不做全量回填。失败清理也不能因为增加了两个子目录就改成递归删除工作区；只清理可确认属于本次创建且仍为空的目录。

## 拖拽整理

本次静态调查发现：侧栏分别保存工作区、大分区、置顶项、会话和自建分组的拖动引用；仅会话与项目有前后插入线。分区和自建分组主要只有 drop 行为，缺少同等可见反馈。项目将整组作为目标，却把插入线画在标题上；置顶和分组调序也没有统一的前后半区语义。

以下为改版验收目标，尚未进行本轮真实浏览器拖拽验收：

| 场景 | 含义 | 反馈 |
| --- | --- | --- |
| 项目调序 | 调整核心工作区顺序 | 在完整项目块之前或之后显示插入线 |
| 项目内会话调序 | 调整同一核心工作区的会话顺序 | 会话行前后插入线，跨项目不接收 |
| 置顶项调序 | 调整展示引用 | 混合项目与会话使用统一落点 |
| 大分区、自建分组调序 | 调整展示顺序 | 整块前后插入线，不暗示嵌套 |
| 会话移入展示分组 | 修改展示标记及组内顺序 | 目标组高亮，明确与普通插入线区分 |

统一拖动源与候选落点状态，处理取消、离开窗口、视图变化和失效源的清理。拖动期间抑制 hover 浮层，收窄按钮与拖动热区的冲突，移到自身或无变化位置不发写请求。

补齐侧栏边缘滚动、空组落点、折叠组悬停展开及结束后的状态恢复。核心写入失败保留或恢复真实排序，并提示错误；键盘与触屏继续保留等价菜单操作，不依赖拖动。

成员列表本轮不额外引入拖拽排序，先把主要成员与链接操作做好，避免扩展出没有明确需求的新排序模型。

## 实施顺序与验收

1. 创建、编辑与状态切换：共用表单、隐藏成员元数据字段、双向 link、空间化与紧凑移除确认
2. 快速对话：收敛新建入口，保留分叉同工作区，补目录访问、`work/outputs` 和短提示词
3. 现有拖拽：统一落点与反馈，补滚动、取消、异步失败及键盘替代行为

每阶段单独验证并提交，避免再次积累成一个跨多轮的大提交。实施时同步更新当前 `ui.md`、设计与验收文档中被替换的旧规则，不把本提案当成已完成的验收记录。

重点回归：隐藏字段不丢数据；链接开启、关闭、冲突、失联目标和部分失败；空间化来回切换与取消；降级后的成员损失和链接保留；分步保存冲突；原生目录选择的网页输入屏蔽与焦点恢复；新建和分叉的不同目标；创建重试与预置目录冲突；所有拖拽的前后落点、取消与真实归属不变。

方案调查阶段直接调用现有投影、新建和草稿模块的内存脚本，确认未描述路径保持 plain、显式 Chat 目标可追加会话、已有 link 切换及编辑内降级被拒绝；当时 6 个测试文件共 181 项通过，仅验证旧实现。第一阶段已替换链接及降级规则，验收结果另记于 `acceptance.md`。
